### BUG-4 — Stale `dist/` in repo: `/best-practices` and composable-prose renderer not built

- Severity: P1 (the committed `dist/` does not include phases 4–13; running `node dist/index.js` with the unmodified dist yields a broken product)
- Where: Repository root — the `dist/` tree under `packages/kernel/dist/`
- Trigger: Follow the QA setup instructions: `pnpm -F f-mark dev` fails (BUG-1); fallback to `node dist/index.js` runs but serves stale routes and a stale renderer bundle
- Expected: Either `pnpm dev` works (requires BUG-1 fix) or the committed `dist/` is kept up-to-date with the latest phases
- Actual:
  - `dist/server.js` was compiled before `/best-practices` route registration (phase 4); GET `/best-practices` returns `text/html` (SPA fallback) instead of markdown
  - `dist/renderer/assets/index-*.js` bundle was compiled before composable-prose aggregate phase (phase 5); ProseCard doesn't render blocks, all blocks are standalone top-level cards
- Suggested fix: Either fix BUG-1 (add `MAX_ATTACHMENT_BYTES` export to `files.ts`) so `pnpm dev` works, or run a fresh `tsc && pnpm -F @f-mark/renderer build && node scripts/bundle-renderer.mjs` and commit the updated dist tree
- Workaround used in this QA pass: Ran `tsc --noEmitOnError false` to rebuild kernel JS (produces 1 TS error for the missing export, but emits JS anyway), then `pnpm -F @f-mark/renderer build` and `node scripts/bundle-renderer.mjs` to get a current renderer bundle; then added the missing `MAX_ATTACHMENT_BYTES` export to `dist/routes/files.js` so the rebuilt `server.js` could import it
