Driven by Playwright MCP on the freshly-built kernel + renderer. Commit at start of this run: `8338ae9 chore: 0.4.0`.

## 🔴 META-FINDING: my earlier "GO" verdict was lying

I previously claimed v0.4 was tested + buddy-verified + ready to ship. The user hit a real bug at first interaction. Walking through the actual browser flow revealed I had been testing against a **stale renderer bundle** the kernel was serving from `packages/kernel/dist/renderer/` — a snapshot from before my Phase 12 work landed. `pnpm -r build` rebuilds `packages/renderer/dist/` but does NOT update the kernel-bundled copy. So my unit tests (which mock fetch) passed, my curl tests passed (because the kernel routes work), and the BUILD passed — but the UI a user actually opened was running pre-v0.4 code.

**The release process needs to run `node packages/kernel/scripts/bundle-renderer.mjs` after every renderer change**, OR the kernel must serve from the live `packages/renderer/dist/` directly. Adding to `package.json` build script would be the right v0.4.1 fix.

## Section K — User's reported bug (HTML response to spawn)

The exact failing flow.

| | Item | Observed |
|---|---|---|
| ✅ | K1-K2 kernel + browser load | works |
| ✅ | K3 click + → Claude | dropdown opens, click works |
| ❌→✅ | K4-K5 spawn returns JSON | **REPRODUCED ORIGINAL BUG**: spawn itself returned 200 JSON, but the follow-up `POST /managed-agents/hook-install-instructions` returned **400 Bad Request: FST_ERR_CTP_EMPTY_JSON_BODY**. The API client sent `Content-Type: application/json` on every POST including ones with no body. Fastify rejected the empty-body+JSON-content-type combination. User saw this as "spawn failed" because the modal that opens after spawn couldn't load its content. **Fixed in commit `9350e4e`** — Content-Type only set when body present; also added a `JSON.parse` try/catch that surfaces non-JSON responses with `"... → 400 returned non-JSON: ..."` so future similar bugs don't look like opaque `Unexpected token '<'` errors. |

After fix: clicking + → Claude succeeds, modal opens with the install snippet. Verified via Playwright network capture: `POST /managed-agents/hook-install-instructions?...` returned 200 + valid JSON.
