# UI Sweep — F-Mark — 2026-07-30

**Verdict:** Two Blockers, both destructive controls that fire with no confirmation — one deletes an untracked file git cannot restore, the other destroys a live agent from a control labelled and shaped like "close this tab". Beneath them, a consistent theme: F-Mark's _guarded_ destructive actions are guarded well, and its most dangerous ones aren't guarded at all.

**Coverage:** 13 sweep units · 12 completed, 1 unrecovered · ~220 controls mapped · ~180 exercised · **2 Blockers · 14 High · 21 Medium · 6 Nit** · plus a 6-component dead-code cluster.

Every finding below carries a live repro, a source citation, or both. Findings discovered twice — once by source analysis, once independently in the browser — are marked and counted once.

---

## Blockers

### B1 · `Revert file` deletes an untracked file with no confirmation — unrecoverable

- **Screen / control:** File viewer → Diff → file-level revert on an untracked file (labelled **"Delete file"**)
- **Expected:** the app gates far milder actions behind `window.confirm` (agent Clear/Remove; `/file-tree`'s "Make active project"), so a destructive file operation should confirm.
- **Actual:** fires immediately. `panels/fileViewer/diff/hunkActionsBar/useHunkActionsBarController.ts:42-58` runs the mutation behind only a `busy` flag; `grep -rn "confirm" panels/fileViewer/diff/` returns nothing. `POST /git/revert-hunk` then runs `git apply --reverse` on the working tree. For an untracked file, `shared/src/git.ts:81-87` offers a file-level action whose own comment (line 78) reads _"untracked / added → hunk (reverse-apply synthetic) + file (delete)"_.
- **Repro:** open a diff for an untracked file → click "Delete file" → gone, no prompt. Two clicks from the Diff tree.
- **Evidence:** exercised live on the fixture `src/untracked.ts`. I then proved it unrecoverable independently: not in `HEAD`, not in the index, no dangling blob (`git fsck --lost-found`), no stash, absent from disk. Corroborated a third time, from a different surface and by a different unit: the `/file-tree` audit searched for the file and got _"No matches"_ — confirming a genuine deletion rather than a stale tree entry or a cache artifact.
- **Mitigation, stated fairly:** the button is **honestly labelled** — `hunkActionsBar/model.ts:14-24` returns "Delete file" for untracked/added and "Restore file" otherwise. This is _an unrecoverable delete with no confirmation step_, not a misleading button. Sharper edge: the per-hunk control on the same file is labelled "Revert hunk" while reverse-applying its synthetic whole-file hunk removes all content — a less honest label for the same outcome.

### B2 · The Terminal tab's per-agent `×` destroys the agent

- **Screen / control:** Right panel → Terminal → per-agent tab `×`
- **Expected:** a `×` on a tab closes the view. The file's own header comment says exactly that — `panels/right/terminal/AgentTerminals.tsx:12-14`: _"No spawn/close — agents are created and ended through the agent lifecycle, not here."_
- **Actual:** `useAgentTerminalsController.ts:144-174` runs `getConfirmToken` → **`goodbye`** → `removeManagedAgent`. It permanently ends the agent and its tmux pane. The only guard is a re-entrancy flag. The control's sole accessible name is `aria-label="Close agent {name}"` on a bare `<X size={11}>`.
- **Evidence:** an auditor destroyed a live agent while believing it was closing a tab — that _is_ the repro. Network trail: confirm-token → DELETE, agent moved to `removed_agents` with `removed_reason:"goodbye"`.
- **Why this is worse than it looks:** the kernel **has** a confirmation mechanism — `goodbye` requires a confirm-token. The UI defeats it by fetching the token programmatically and spending it immediately, so a server-side guard designed to force human confirmation delivers none. Meanwhile the right-panel surface guards the _same_ `goodbye` behind `window.confirm` (`RightAgentControls.tsx:163`).
- **Severity note:** the auditor filed this High; I raised it to Blocker. The rubric names "destructive action with no confirm" explicitly, and the mislabelling makes accidental triggering likely rather than theoretical.

## High (14)

**H1 · Confirmation parity is broken for identical actions.** Chip popover fires _Say goodbye_ / _Clear context_ with no dialog (`ParticipantStrip.tsx:160-198`); the right panel guards both with `window.confirm` (`RightAgentControls.tsx:126,163`; `AgentPopover.tsx:410,423`). Verified live in both directions — the chip path produced confirm-token → DELETE with no dialog; the right-panel path raised `confirm("Remove Nora?")` and Cancel genuinely cancelled. **With B2, F-Mark has two unguarded paths to destroy an agent and one guarded path.**

**H2 · An embedded TodoCard can never show its cascade confirmation.** `cards/ProseInlineBlock.tsx:102,110` passes `allEvents={[event]}` — only the todo itself — so descendant computation always sees zero children. Live: removing an embedded parent produced no dialog and one client POST; the kernel then auto-wrote a `removed` event for the child 1 ms later. **The child was deleted with the user never told it existed.** The standalone tree card correctly asks _"Remove this task and 1 subtask?"_. Critically, **no UI path embeds todos — only agents do**, so the broken surface is the agent-authored one, which is F-Mark's core use case.

**H3 · Permission scope can misrepresent what is being granted.** `cards/approvalScope.ts`: `classifyApprovalSuggestions` is first-wins-per-scope, so a second materially different approve option is silently dropped; `scopeOfSuggestion` regex-maps `/allow access|and allow/` to `always`. Live, with a 5-suggestion payload: 5 provider options collapsed to 3 controls, "Always" mapped to the **narrow** `.bin/`-scoped grant and rendered as _"Always allow this without asking"_, while the genuinely blanket option was invisible. This is the one screen where a human makes a security decision on an agent's behalf.

**H4 · A runtime the UI reports "ready" can fail to launch.** `/env-probe` judges availability with an augmented on-disk search including `~/.local/bin`, `~/.bun/bin` and mise shims (`routes/envProbe.ts:42-44`, `runtimes/executableSearch.ts:52-65`); the tmux spawn passes the bare name and resolves via PATH only (`tmux/manager/sessionLauncher.ts`). `resolveExecutableForExec` exists to fix precisely this and is called from exactly one place — `mcpInstall/index.ts:59` — never the spawn path. Aggravated by diagnosability: the failure surfaces as HTTP 500 _"tmux set-option failed: no server running"_, naming the wrong subsystem, and `managed-agents/status` afterwards shows no trace.

**H5 · The `connected` predicate is too permissive and gates three controls.** `AgentChipEditorPopover.tsx:87` excludes only `offline` from a six-state enum, so `launching`, `stale`, `pane-dead` and `hook-not-installed` all count as connected — enabling `canUseLiveControls`, `canClear`, and **`canOpenTerminal`** (a dead pane still offers Terminal). Live-proved for Clear (fired at `launching`, server 409'd).

**H6 · The mention picker has no Escape, no outside-click, no auto-close after send — and blocks clicks underneath.** `components/agentMentionPicker/AgentMentionPickerView.tsx:24-46` hand-rolls a `<div>` instead of the shared `popovers/Popover`. Found independently in **two** surfaces (compose bar, comments thread); Playwright's own retry log names the popover intercepting pointer events.

**H7 · A failed tool call doesn't open by default in historical turns.** `cards/arbitraryGroup/ArbitraryGroupBody.tsx:110` returns `false` rather than `undefined` for non-streaming groups, and `toolUseCard/useToolUseDisclosure.ts:52-55` treats `false` as an instruction rather than "no opinion", clobbering `ToolUseCard.tsx:31`'s `success === false` default. Since nearly every group a user sees is historical, **open-on-failure is effectively dead outside a live turn**.

**H8 · Choices-card mutations fail completely silently.** `cards/choicesCard/useChoicesCardModel.ts:71-99` has no try/catch; a failed POST yields only an unhandled rejection — no toast, no inline error, no stuck busy state. Systemic across the ChoicesCard family. Secondary risk: when ends-turn is on it chains `postTurnEnd` and `wakeSession`, so a mid-chain failure can record the choice but never end the turn.

**H9 · Comment-activity rows show a raw event filename.** `cards/CommentActivityCard.tsx:52` returns the fallback for any non-prose target, so the feed reads _"You commented on 20260730T114700.042Z_ag-sweep-01.choices.json"_. Leaks into the right-panel Comments tab too.

**H10 · Command-palette agent rows advertise a destination they can't reach.** `modals/cmdk/sources.ts:409-417` builds the sub-label from `session?.slug ?? active_session` but sets the navigation target from `active_session` alone. Where the first resolves and the second is null (11 of 12 agents in the fixture), the row shows a session name, the palette closes, and nothing happens.

**H11 · Tab/Shift+Tab on an uncommitted draft todo silently discards the typed title.** `panels/todoTree/todoTreeContent/TodoTreeLevel.tsx:75-86` vs `:90-107` render `<TodoTreeDraftItem key={draft.id}>` at two structurally different positions; indent/outdent mutate exactly the fields that decide which, so React remounts the row and the title — held only in the old mount's local state (`cards/todoItem/useTodoItemInputs.ts:44`) — is lost. Committed todos are unaffected, which is why it hides.

**H12 · Favourite ★ also opens the file, and the code comment asserting otherwise is false.** `panels/right/files/FileRow.tsx:173-174` binds the row's open to `onMouseDown`/`onMouseUp` (deliberately, per its comment at `:100`); the star at `:200` uses `onClick` + `stopPropagation`. Native order is mousedown → mouseup → click, so the row wins every time. The comment at `:141` — _"Star button has its own onClick with stopPropagation, so we don't reach here"_ — cannot be true.

**H13 · `MonacoDiffRenderer` throws an uncaught error on nearly every diff interaction.** _"TextModel got disposed before DiffEditorWidget model got reset"_, 5 occurrences across revert-hunk, revert-file, diff-mode switch and diff-style switch. The UI doesn't visibly break. **Root cause not source-proven** — `monacoDiffRenderer/MonacoDiffEditor.tsx:39-40` passes `original`/`modified` declaratively with no manual disposal, consistent with a library unmount-ordering fault; reported as observed rather than diagnosed.

**H14 · Resolving a comment makes it vanish permanently — and the same defect leaks a raw sentinel.** One root cause, two symptoms, found by two units that never spoke.
`state/aggregate/EventAggregator.ts`: `buildSupersedorOf` (`:174-185`) maps **every** `supersedes` reference with no distinction between a genuine edit and a resolve/unresolve _marker_; `superseded` (`:135`) feeds `buildVisibleEvents` (`:250-260`), which drops the original comment from `visible` the instant it is ever resolved. Reopen cannot restore it. Meanwhile `buildCommentsByTarget` (`:488-503`) excludes only _removed_ markers, so the marker itself survives.
⇒ **Symptom A (High):** the comment's rail pin and its `CommentActivityCard` row disappear permanently; the right-panel tab still renders it via a chain-aware path, proving the data is intact — this is a rendering/filtering defect, not data loss.
⇒ **Symptom B (Medium):** the all-sessions Comments view prints the literal `_resolved_` sentinel as the comment body (`panels/Comments.tsx:104`).

## Medium (21)

1. **Todo cycle protection is read-side only.** `services/events.ts`: `wouldCreateCycle` (`:564`) is called only from `buildTodoTree` (`:580`/`:684`); `writeTodoEvent` (`:773`) never validates. Live: `B.parent=A` then `A.parent=B` both returned 200; the tree silently re-roots both with no error. Reachable via the API — i.e. by agents.
2. **Custom runtime `Remove` fires with no confirmation** (built-ins correctly disabled, `RuntimeTable.tsx:144`). Recoverable via one `PUT`, and **removing a runtime backing a live agent is unguarded** — though the kernel decouples a running process from its registry entry.
3. **Every HTML bundle is assembled twice, so its JS runs twice.** `services/events.ts:927` assembles at write time; `routes/raw.ts:110` assembles the already-assembled file again at read time. `events/htmlBundle.ts` `removeCompanionAssetTags` strips only _external_ refs, not the inlined blocks the first pass emitted. Proven live: 4 asset tags where there should be 2. Double-binds event listeners in every `fmark_post_html` / `fmark_post_alternatives` bundle — the core "show me a mockup" flow.
4. **`AGENT.md` documents three attachment endpoints that 404.** Listing (`GET /sessions/:id/attachments`), rename (`PATCH …/:file_id`), and comments (`POST …/:file_id/comments`) all return 404; only upload and content exist. `routes/files/attachments.ts:121` registers the collection path as `app.post` only ("Upload-only"). Line 111 also promises `disk_path`/`raw_url`/`content_url`, which no route produces. **The drift is in the shipped template**, so every project receives it — and this is the protocol agents are told to follow.
5. **Staged-but-unsent attachments orphan server-side with no reap path.** `findAttachment` (`routes/files/storage.ts:96-110`) searches only committed `file` events, so a staged blob is invisible to every route that could find or delete it. **Amplifier found on disk: forking copies the orphan into the fork.** Cleaning it at the end of this sweep required direct filesystem access — which is the finding.
6. **Double-submit race writes duplicate prose** (same-tick only; `sendButton/model.ts:46-65` gates on async React state with no synchronous lock). Honestly downgraded by the auditor after a realistic `dblclick()` produced only one POST.
7. **Every write to an agent-assigned todo re-fires the wake.** No PATCH exists, so `assigned_to` is carried forward on every update and `shouldWakeAssignedAgent` fires each time — 4 wakes across 4 unrelated status toggles.
8. **Duplicate "Refresh" tile for removed agents** (`AgentPopover.tsx:292` and `:382`).
9. _(merged into H14 — the `_resolved_` sentinel leak)_
10. **Avatar preset picker can close the entire Settings modal**, discarding edits — its own document-level outside-close handler plus a non-portaled in-flow panel means a click can land on the backdrop mid-interaction.
11. **No focus trap on any ModalRoot modal** — opening doesn't move focus in, and the first Tab lands on background content behind the backdrop.
12. **Touch targets below minimum**, two surfaces: top bar 28×28 / 32×32 at 1440px (not a small-screen artifact), cmdk rows 34px.
13. **Tablists have `role="tab"` without roving tabindex or arrow-key handling** — systemic; `role="tab"` appears in 21 files.
14. **No responsive layout below desktop width** — real horizontal overflow at 768px and 375px; at 375px `.compose-dock` collapses to `width:0`, making the composer non-interactive.
15. **"Changed outside tree" badge hard-codes "R"** — `RightDiffTree.tsx:462` renders `status.includes("deleted") ? "D" : "R"`, mislabelling 44 untracked files as "Renamed".
16. **`IntegrationSetupModal` cannot be dismissed with Escape** and its backdrop blocks the page — mounted outside `ModalRoot`'s shared escape handling.
17. **Presence can lag or stick at `launching` after Reconnect.** Reported at full strength, then **retracted to this weaker form by the auditor itself** after it observed recovery to `online`. No pinned cause.
18. **Empty-session state conflates "0 events" with "no agent connected"** — no distinct feed-empty placeholder.
19. **Inline comment popover has no viewport-collision handling** — for a line near the top of the scrolled feed it renders over the app's own sticky header and tab bar.
20. **`FileCommentCard`'s focus hitbox is partly stolen by its inner path pill**, which has its own `stopPropagation` + open-file handler.
21. **`/file-tree` session selection is not durable** — the switcher updates the view correctly but never writes `history.pushState` or `lastFocusedSessionByPath`, and `useFileTreeLaunch.ts:4-6` reads `window.location` once via `useMemo(…, [])`. Reloading the same URL silently reverts the choice with no signal.

## Methodology notes worth carrying forward

- **Two auditors' claims were wrong and had to be overruled.** A spawn failure diagnosed as a "tmux race" was actually pane-command-not-found — proved by a controlled pair of experiments (a valid command never fails; a missing one always does). Filing the race would have sent someone hunting a timing bug that doesn't exist.
- **Two auditors retracted their own overclaims** when evidence contradicted them, and one refuted a premise of mine with source evidence. That self-correction is why the remaining findings are trustworthy.
- **A summary disagreed with its own report** (claimed 3 High, filed 1). All counts here are recounted from the artifacts, never from summaries — including mine, whose running tally in chat was inflated by double-counting findings discovered both by source analysis and in the browser.
- **Delivery, not auditing, was the weak link.** Four auditors' configs forbade writing `.md` files; two finished silently; one was unrecoverable. The audit work itself was consistently strong.
